## 1. 任务目标

在好友档案 Longitudinal Phase 1.1 基线（`4eeb5c4`）之上，修复三类用户实际
遇到的问题：

1. **分页滚动体验**：点击上一页/下一页时页面先发生一次明显位移再定位；
   在导航附近继续翻页仍执行不必要的自动滚动；分页表格有时保留上一页的
   内部滚动位置，导致新页不是从第一行显示；选择「我是」等普通控件时也
   出现不必要的页面跳动。
2. **证据编辑器崩溃与串档**：同一消息同时入选「支持性证据」与「相反证据」
   时，`_evidence_candidates()` 直接拼接两份列表 → 同一 index 出现两次 →
   `_render_evidence_editor()` 用 index 构造 widget key → 抛
   `StreamlitDuplicateElementKey`（用户实测报错 `friend_evidence_del_106`
   即 index 106 重复）。
3. **②确认阶段「历史档案」查看状态**：查找成功后没有取消查看入口；
   `_reset_chat_state()` 不清理 `history_friend_id` / `history_matches`
   → 替换聊天后可能显示上一位好友的历史。

约束：不改九问、评分、时间排序、分析 schema、历史数据库结构；不调用真实
Jev；不删用户缓存与档案；不 tag / 不发 Release。

## 6. 已排查过的错误与无效尝试（避免重复排错）

### ① `st.form` 死锁（已修，重要）
- 现象：真实浏览器里「应用昵称映射并重新解析」按钮永远灰色点不动。
- 根因：`st.form_submit_button(disabled=表单内控件的值)`——表单内控件的
  值在提交前**不会**送到 Python，所以 `disabled` 恒为 True。
- 无效尝试：曾以为是 Enter 提交了表单导致按钮消失（诊断时看到
  `submit count: 1` 但 click 超时）。
- 正解：提交后校验 `if sel_me == "（未指定）" and sel_ta == "（未指定）": st.error(...)`。

### ② `st.session_state` widget 写入（已修，重要）
- 现象：删除好友档案时抛 `StreamlitWidgetAlreadyInstantiatedError`
  （`friend_confirm_delete`），handler 中断，**数据库已删但界面停在旧档案**。
- 同类问题：`_clear_history_view()` 里残留过一行
  `st.session_state["history_alias_input"] = ...`，同样抛这个错，
  导致取消查看后提示不显示。
- 正解：`_queue_widget_reset(*keys)` 排队 + `_apply_pending_widget_reset()`
  在 widget 创建前 `pop`。
- 副作用：`st.session_state.setdefault()` 在真实脚本运行里**不可用**
  （只有裸 SessionState 支持）→ 保存标记曾因此失效。已改显式 get/set。

### ③ 表格内部滚动（**未解决，优先排查**）
- 现状：单次翻页（顶部或底部）内部滚动都能归零
  （`top_turn_inner_scroll_reset` 1037→0、`bottom_turn_inner_scroll_reset` 0）；
  但「连续翻页多页之后再滚内部到末尾、再翻一页」时 `innerTop` 停在 1037，
  且 `rows` 数量不变（11→11）——看起来这次点击**没有生效**
  （见④），而不是归零失败。
- 已排除：key 重新挂载是有效的（`__probeMark` 变化证明节点重建）；
  `findTableAfter()` 已能正确定位表格（原来紧邻假设失败，中间夹 `<script>`）。
- 待办：在新电脑上先确认「点击是否真的翻了页」（打印页码 + 锚点 nonce），
  再判断内部滚动归零是否真的失效。

### ④ Playwright 点击被丢弃 + 脚本超时（未解决）
- 现象：`page.locator('button:has-text("下一页")').last.click()` 偶发无效，
  页面页码不变、无报错。加 900ms 等待 + 3 次重试后能翻页，
  但脚本最终仍在一个 `label:has-text("重新选择身份")` 的 click 上超时——
  「重新选择身份」是 `<button>` 不是 `<label>`，已定位但**尚未在脚本里改**。
- 无效尝试：`force=True`、`scroll_into_view_if_needed()` 都试过，
  不是可见性问题；是 glide 重渲染瞬间的竞态。

### ⑤ 其它无效尝试（记录备查）
- 曾用 `st.components.v1.html` / `st.iframe` 做滚动锚点：前者已废弃、
  后者拒受 `height=0`。最终用官方 `st.html(unsafe_allow_javascript=True)`。
- 曾把「锚点脚本先把所有可滚动祖先 scrollTop 归零再 scrollIntoView」：
  这就是用户看到的「先跳一下再定位」，**已删除**，改为按锚点在每个容器内
  的真实偏移一次算好一次赋值。
