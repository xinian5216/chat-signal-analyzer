# AGENTS.md

Repo-specific guidance for OpenCode / AI sessions. Everything here was verified against the current code; omit nothing, add no fluff.

## Environment (Windows)

- Use the project venv: `.venv\Scripts\python` — there is **no usable system Python** (`python` on PATH is the Windows Store stub, no `py` launcher).
- The console mangles UTF-8 Chinese. When a script prints or reads Chinese, run `python -X utf8 ...`; edit files with file tools, not shell `echo`.

## Commands

- Tests: `.venv\Scripts\python -m pytest tests -q` — 691 tests (412 + 201 evaluation/isolation/v3/field-study/timeline/wechat), ~56s. Single test: `... -m pytest tests/test_scoring.py::test_transform_noul_noise_floor -q`. Run from the repo root (`pytest.ini` sets `pythonpath = .`, `testpaths = tests`).
- App: `.venv\Scripts\streamlit run app.py` (dev mode).
- Benchmark (offline, deterministic): `.venv\Scripts\python scripts\evaluate.py --fixtures` (real mode `--real --yes-run-live-api` + `TYPESAFE_API_KEY` is human-only, never run by CI; per case it analyzes **only** that case's TA target via `only_indices` — N cases = N requests — `--report` writes the aggregate comparable via `--compare`, `--raw-report` stores raw model outputs separately).
- Portable build: `.venv\Scripts\python -m PyInstaller --noconfirm --clean SignalLens.spec` → `.venv\Scripts\python scripts/frozen_smoke.py` → `.venv\Scripts\python scripts/package_portable.py`. Needs `TYPESAFE_API_KEY` in the gitignored `.env`; without a key the UI shows a friendly hint and does not crash.
- Real-API smoke test — **the only script that calls Jev** (5 constructed messages, then fully cached): `.venv\Scripts\python -X utf8 scripts\smoke_test.py`.

## Testing rules (hard)

- Tests must **never** call the real Jev API — mock `client.system_one` (pattern: `FakeClient` in `tests/test_analyzer.py`).
- Tests must not read the real `.env` and must not depend on `.jev_cache` — use `tmp_path` fixtures.
- CI (`.github/workflows/tests.yml`) runs `pytest tests -q` on ubuntu-latest / Python 3.11 with **no API key**. The `pytest` status check is required on `main`.

## Architecture

Single Streamlit app, flat modules, no package:

- `parser.py` — chat text → messages; **format-isolated** parsing via `detect_format()` (`wechat_blocks` / `legacy_colon` / `time_name` / `unknown`). In `wechat_blocks` mode a message ends only on a valid sender candidate + a next-line **fullmatch** timestamp — no legacy `speaker: content` / `time name` guessing inside BODY, so long technical bodies (code, JSON, `已知现状：`, URLs) never create fake participants. Legacy colon mode remains a separate mode; legacy `speaker: content` / `time name` branches isolated from URL schemes and in-body time substrings; participant detection reads **only** parsed `raw_speaker` (no repetition requirement); non-text media placeholder filtering (`content_type` text/media/mixed, WeChat media filenames stripped, real Unicode emoji preserved, voice duration → local-only `duration_seconds`)
- `merge.py` — local chunk append / fingerprint / dedup (0 Jev API). Fingerprints and chunk info are local metadata only: they must never enter Jev state, cache keys, or default report bodies
- `privacy.py` — local masking before anything leaves the machine
- `timeline.py` — **message timeline sort (pure logic, 0 Jev)**: after merge/dedup and **before** Context Builder, messages with a full legal `YYYY-MM-DD HH:MM` timestamp are sorted ascending (cross-day/month/year, and robust to chunks appended newest-first); timestamps must be **real calendar moments** (`_is_real_datetime`: leap years 4/100/400, month-end days, hour 0~23, minute 0~59) — `2026-02-30`, `2026-13-01`, `25:61` are rejected, counted as unparseable and never enter the anchored timeline; same-minute messages keep the user's paste order within a chunk, while identical timestamps **across chunks** are flagged `ambiguous_exact_tie` (never fabricated) via a local `_chunk_idx` tag that can never leave the machine (build_state's outbound allowlist keeps only speaker/text/time); `HH:mm`-only / missing / unparseable timestamps are never date-guessed into the timeline — they keep their determinable local order and are reported via `TimelineResult.summary_text()` (full / time-only / missing / same-instant-unconfirmed counts); analysis requires explicit user confirmation when order is genuinely uncertain (mixed full+partial, multi-chunk partial, cross-chunk same-instant), and any re-import / append / re-parse that changes the order signature resets that confirmation. `migrate_bindings` moves **both** auto and manual media bindings by fingerprint across reorder (unique match only; dropped bindings force re-confirmation); `order_signature` invalidates all index-dependent state (analysis results) when order changes; `preview_page`/`page_time_range` power the preview paging
- `scroll_anchor.py` — **paging scroll anchor (pure UI plumbing, 0 Jev)**: `request_scroll(area, page)` / `consume_scroll(area)` / `clear_scroll_request(area)` register one-shot scroll requests with a monotonic nonce per area (areas are isolated: import preview vs all-messages); `_scroll_anchor(id, nonce)` renders the zero-height anchor via `st.html` trusted channel and scrolls every scrollable ancestor (incl. `section.stMain` and the dataframe inner scroller) back to the top so the new page's first row is in view; no private DOM selectors, no chat text in the HTML
- `friend_history.py` — **local friend profiles + immutable analysis history (0 Jev)**: separate SQLite file (`paths.friend_history_db_path()`, never the analysis_cache) with `friends` / `friend_aliases` / `history_runs` / `history_messages` / `history_evidence` / `history_results`; Phase 2A 起带**版本号增量迁移**：`schema_meta` 表记录版本（当前 v2），v1 老库打开时在同一显式事务里补建 `behavior_events` / `behavior_event_audit` 并写入版本号——失败整体回滚（测试注入坏 DDL 验证：无半套表、v1 数据完好、重开即恢复），不可变快照定义不变；identity is a random `friend_id` — WeChat nicknames, remarks and aliases are **lookup keys only** and an alias matching several profiles is never auto-merged; every save writes a new immutable snapshot (run_id, friend_id, analysis started/completed, chat first/last time, full-time ratio, analyzed/failed/media-skipped counts, stable message fingerprints + de-duplicable case signature, schema version, requested model **and actually returned model version**, the nine answers, stats and summary text, plus user-selected anonymized evidence snippets); short-lived connections like `storage.Cache`; no logging, no nicknames in history tables, no chat text unless the user opts into evidence snippets (PII-masked, truncated, capped); 行为事件 CRUD（`save_event` 幂等去重 / `list_events` / `update_event` / `set_event_status` / `delete_event` / `audit_of`）与「确认/排除」状态的 (friend_id, event_identity) 部分唯一索引也在这里；**所有 snippet 写入路径（手动添加 / 候选确认 / 事件编辑）在 store 层统一过 `anonymize_evidence_text` 脱敏兜底**（mask + 空白折叠 + 截断到 `EVIDENCE_MAX_CHARS`），不依赖调用方已处理；说明 / 主观感受不做自动脱敏（UI 明确提示可能含 PII）
- `behavior.py` — **行为事件层（Longitudinal Phase 2A，本地，0 Jev）**: 独立的「行为事件」模型（不是九项评分的平均）：四个观察方向（尊重与边界 / 关心与回应性 / 主动性与投入 / 好感与关系性质）各有固定行为类型集合（如 `refusal_reaction` / `pressure_or_disdain` / `continued_attention` / `romantic_expression`——普通友好、亲密友情、特殊关注、明确浪漫表达**分别处理**）；`generate_candidates()` 用确定性规则（连续同说话方 turn、明确提问、后续安排、拒绝/关心/邀约/浪漫措辞）从当前导入生成**待人工核对**的候选，`history_candidates()` 只用历史快照的既有指标辅助筛选且一律标注“无聊天正文”（绝不凭指纹/旧总结重写正文）；事件身份 = 消息指纹集合 + 方向 + 行为类型（重复导入不重复计算）；一分钟内五条关心 = 一个候选（同一次互动合并，边界用户可调）；`build_behavior_report()` 分方向呈现已确认事件、支持/相反证据并列（不抵消成均分）、分期分布表 + 「数据不足不得宣称改善或恶化」、限制与缺失、用户主观感受独立成节——**不生成任何尊重分/喜欢概率/人格标签**，正常争论≠不尊重、普通关心≠浪漫、回复快慢≠关心。Phase 2A.1 硬约束：`history_candidates` 的身份用 run 里**真实保存的消息指纹**（不是 run_id:index），同一条历史消息跨 run 重叠可识别；历史候选的消息编号属于原 run，默认禁止用当前聊天下标改边界（防「历史第20条与当前第20条完全不同」错关联），将来关联必须先过 `current_matches_by_fingerprint` 指纹验证 + 人工确认；`generate_candidates` **不截断**（先全量生成 → `pending_candidates` 按身份剔除已处理 → 调用方分页，每批只渲染少量控件）；`build_event_dict` 写入前校验方向/行为类型组合（非法组合 raise ValueError，UI 捕获后拒绝落库）；候选**不在生成阶段限流**；`generate_candidates_with_meta` 返回截断元信息（generated/returned/cap/truncated），`truncation_notice` 生成「部分候选未显示」提示供主界面使用
- `longitudinal.py` — **local cross-run comparison (0 Jev, no new scores)**: fingerprint-based overlap / duplicate detection (same time + different content is never a duplicate), `stale_targets` for “the full context changed → do not blindly reuse the per-message cache”, `eligibility` gating (schema / model-version / missing chat time / overlapping ranges → reevaluate instead of faking a trend), `future_leakage_allowed` so only history older than a target can join its context, `continuity_gap_days`, and the local 「长期观察」 Markdown report (per-run chat coverage, existing behavior stats only, supporting + counter evidence, missing-data notes, explicit disclaimers — no 尊重分 / 喜欢概率 / personality labels / reply-latency inference)
- `context_builder.py` — **Context Builder v2** (pure logic, zero Jev calls): turn-aware, bounded context selection. A turn = consecutive messages of the same speaker; from each TA target the builder walks turns backwards and keeps the most recent complete turns (esp. the nearest me-turn the TA is replying to) under three simultaneous budgets — `CONTEXT_MAX_TURNS=8` / `CONTEXT_MAX_MESSAGES=12` / `CONTEXT_MAX_CHARS=4000` (chars ≈ sum of message text lengths, no tokenizer). Replaces the old mechanical `context[-5:]`. Never truncates inside a message (P0: the message immediately before the target is always kept whole, even past the char budget); the target itself is never budget-limited; no future messages ever enter the window; no semantic/keyword retrieval — turn + recency + budget only. Output is flattened back to chronological `list[dict]`; internal turn metadata never enters Jev state
- `analyzer.py` — one Jev `system_one` call per TA message carrying all 9 questions (2 Choice + 5 Score + 2 Noul; never split the questions of one message). `build_state()` is the final outbound allowlist (only normalized role, redacted text, optional time, and the analysis rule may leave the process; parser metadata such as `raw_speaker` must stay local) **and** delegates context selection to `context_builder.select_context`; the result entry's `"context"` is the exact window sent to Jev (UI shows what Jev saw). Cache is consulted first: only misses go to a **bounded** ThreadPoolExecutor (`JEV_MAX_WORKERS`/`SIGNALLENS_JEV_CONCURRENCY`, default 4, clamped 1..8), with worker-local `TypeSafeClient` instances (the SDK does not promise thread safety) that are closed afterwards; results are reassembled in the original target order. Pure-media messages (`content_type == "media"`) are never targets: zero API calls, excluded from every statistic
- `evaluation/` + `evaluation.py` + `scripts/evaluate.py` — **offline evaluation harness**: deterministic benchmark over 34 fully fictional cases (`evaluation/cases.json`, categories A–Z). Each case states expectations (choice allowlists, score `[min,max]` ranges, Noul probability bounds), `must_not_infer` anti-overclaim contracts (romantic_from_care_alone / romantic_from_late_night / distancing_from_slow_reply / …, thresholds centralized in `MUST_NOT_INFER_RULES`), acceptable ambiguity, and optional context checks (no future-message leakage; required turn contents must be in the Context Builder v2 window). `evaluate_case`/`evaluate_cases` do constraint checking only — no Jev call, no second LLM judging Jev. Aggregates: per-case pass/fail, per-constraint pass/fail, dimension failure counts, false-positive categories (romantic / distancing / special_attention overclaim / warmth-estimation / context_misunderstanding / future_message_leakage / media_guessing). `--cases` / `--fixture-file` select alternative case sets (distancing / phase2 / contrast / v3.1 revisions); `--from-raw` rebuilds aggregates offline (case-identity guard + schema provenance, never guesses the version; unknown is recorded as unknown); `--compare` refuses (exit 3) when case-set identity differs or is missing and prints a schema-semantics-changed warning with neutral wording across schemas. `--real --yes-run-live-api` + `TYPESAFE_API_KEY` is the human-only live mode (double gate + pytest/CI refusal; batch preflight validates every case target before any request; case-setup errors are recorded as `case_setup_error`, distinct from `api_error`). `evaluation/reviews/` holds human review records (distancing_v3 / phase2_design_review / phase2_design / distancing_v31_revisions / main34_v31_revisions / v32_design / contrast_v32_errata); `evaluation/reports/` is gitignored
- `evaluation/field_study/` + `field_study.py` — **independent human-validation facility (pilot preparation; no recruitment yet, never run in CI)**. v1.1 scientific hardening: **item-level metrics** (multi-observer labels are aggregated into an item reference — majority / lower median, `contested` excluded — so n counts items, not annotation records; reports state items / groups / annotation records / independent observers); **group-level cluster bootstrap CI** as the primary uncertainty measure (fixed seed 20260923 × 2000 rounds, recorded in the report; Wilson CI is descriptive only, since one chat pair can contribute many items); **Krippendorff's alpha** (nominal / ordinal, self-implemented, multi-rater and missing-data tolerant) as the precondition for calling observer labels a human reference; **Noul**: ROC-AUC + PR-AUC only — raw Noul never gets a Brier score, Brier/log-loss require a dev-fitted Platt calibration pinned in the freeze manifest and may only be computed on the blind partition; **de-identified item dataset** (`item_schema.json`) is the single source for both model input and observer text via `render_item_text(item)`, and the freeze manifest binds item + annotation SHA256s (any item-text change fails verification); **role enforcement** (sender_intent only from sender, receiver_felt_experience only from receiver, observer dims only from observers, participant_perception kept separate from observer gold); **blind-lock manifest** (dataset versions, both hashes, partition, SignalLens commit SHA, chat-signal schema, model alias + observed model version, metric-definition digest, calibration) with the retire-after-reveal policy; **recall_delay_bucket** (no exact timestamps) with the retrospective-self-report caveat; `evaluation/field_study/` also holds PROTOCOL v1.1 (pilot ≠ confirmatory validation; sample size is decided after the pilot measures class balance / alpha / abstention / group correlation), both consent templates, de-identification rules, withdrawal/deletion process, ANNOTATION_GUIDE.md (operational definitions + 0–4 anchors + unsure/insufficient rules), and synthetic-only examples. Tests (`tests/test_field_study.py`) use synthetic data exclusively; the project is a chat-behaviour analysis tool — no clinical diagnosis, no claim of reading minds; no real personal chat may be collected or uploaded without separate approval
- `scoring.py` — v2 weighted aggregation; **all weights and thresholds are centralized at the top of the file**
- `storage.py` — SQLite result cache
- `report.py` — Markdown / JSON / summary export
- `ui_helpers.py` — pure display helpers only (short labels, media badges, message filtering, overview layout data); **no scoring/business logic may live here**
- `media.py` — `MediaAsset`, upload/clipboard limits, conservative placeholder→image binding. **Image binaries must never enter Jev state, SQLite, or reports**
- `rich_paste.py` — rich-paste component wrapper + `assets_from_uploader` fallback bridge
- `vision.py` — vision interface stub, **disabled by default** (no vendor chosen yet)
- `components/rich_paste/index.html` — vanilla-JS Streamlit custom component for the Clipboard Probe. Note: on Streamlit 1.64 the component value **cannot** reliably reach Python (verified), so the Probe is **self-contained inside the iframe**; do not re-litigate the protocol without new evidence
- `tools/clipboard_probe/` — probe report formatting + the real-device WeChat test checklist
- `paths.py` — single place for mutable data locations: dev mode keeps the legacy repo paths (`.jev_cache/cache.db`, `.env`, `.media_cache/`, `logs/`); portable (frozen or `SIGNALLENS_DATA_DIR`) puts everything under `data/` next to the exe (`cache.sqlite3`, `settings.env`, `media_cache/`, `logs/`, `runtime.json`). A non-writable data dir raises a friendly `DataDirError` — it must never fall back to AppData/TEMP
- `settings_store.py` — local config (API Key only) with priority: process env > `data/settings.env` > dev-mode repo `.env`. Never logs/prints/returns the key itself
- `portable_launcher.py` + `SignalLens.spec` — PyInstaller **onedir** Windows portable entry: exe-relative data dir, port 8765~8785 bound to 127.0.0.1 only, single instance validated by PID + port + `/healthz`, bounded startup poll + `webbrowser.open`, child Streamlit always reaped, console kept on purpose (no secrets printed)
- `launcher/` — Windows `install.bat` / `start.bat` (developer/fallback tools, script-relative paths, single-instance guard, localhost only); the normal-user path is the portable ZIP
- `app.py` — Streamlit UI: 4 stages (input → confirm → analyze → results), all API calls happen only inside `run_analysis`. Results are rendered through **server-side lazy navigation** (`st.segmented_control` + if/elif), never `st.tabs`: tabs execute every tab's Python on each rerun, which kept the script "running" for seconds after results were visible. “全部消息” is paginated (25/page) with **top and bottom navigation plus a `scroll_anchor` module** (`st.html` + `unsafe_allow_javascript=True` — the official trusted-HTML channel, never a `st.markdown` script injection); a per-page **nonce** makes every page turn render unique HTML so consecutive turns 2→3→4 each re-mount and scroll (identical HTML would be de-duplicated by Streamlit); requests are only registered by paging button callbacks (`request_scroll`/`consume_scroll`, one-shot) so plain reruns / expanding metrics / ticking checkboxes never auto-scroll; the anchor scrolls the real Streamlit scroller (`section.stMain`, `window.scrollY` is always 0) plus the glide-data-grid inner container, and lands on the new page's first row; the import preview (② confirm stage, PREVIEW_PAGE_SIZE=40/page, 最近/最早 15 条 + 分页浏览全部) renders top and bottom navigation through **one shared renderer** (_render_preview_nav, symmetric ◀ 上一页 | 居中页码 | 下一页 ▶, date range as its own caption row) with an isolated scroll area; both paginators disable prev on the first page and next on the last page, and a click only sets a scroll request when the page index actually changes (_goto_preview_page guard); switching filter mode or media events resets the page index; paging only reads already-computed local results (0 Jev API, no cache invalidation, no schema change); reports are built only when the report view is open. The ④ results stage also has an optional 「长期观察」 view (local friend archive + longitudinal comparison: choose/create a profile by nickname/remark/alias, save the finished analysis as an immutable snapshot — **off by default, never auto-saved** — browse history, inspect overlap with the current import, export or delete a profile and its history; the sidebar's cache button clears **only** analysis_cache and never touches the archive. **串档防护**: `friend_binding` records the TA identity that was current when the profile was chosen; replacing the chat, remapping the identity, or an append that introduces a new participant invalidates it (`_sync_friend_binding` runs on every confirm-stage render, so no code path can forget to clear it) and the user must explicitly pick a profile again — appending more of the **same** person's chat keeps the binding. **保存标识** = (analysis_revision, case_signature) → {friend_id}: saving the same analysis to a second profile is allowed but demands an explicit 串档 confirmation, while re-saving to the same profile only warns about the duplicate case. **证据隐私**: keeping evidence is opt-in and shows the final masked preview (editable / removable per item) before anything is written, and says plainly that regex masking cannot guarantee anonymity; widget-backed state is never written after instantiation (a real browser bug where deleting a profile crashed with StreamlitWidgetAlreadyInstantiatedError), so checkbox resets go through a pre-widget `friend_checkboxes_reset` flag; deletion notices survive the post-callback rerun via `set_input_notice`; the delete UI and README state that removing a row is **not** a secure wipe of the DB file, its -wal/-shm, backups or previously exported JSON); `analysis_state` is an explicit state machine (idle/pending/running/complete/error/interrupted) — a fresh rerun that still sees `running` means the previous run was interrupted, and is recovered automatically. Phase 2A 起同一视图内嵌「长期行为观察」面板（`show_behavior_panel`，0 Jev API）：确定性候选 + 历史既有指标候选**每批 5 条分页**（`BEHAVIOR_PAGE_SIZE`，不同时创建几百控件）；每条候选在 `st.form` 里可改方向 / 类型 / 覆盖范围 / 立场 / 说明 / 脱敏片段后确认或排除（表单提交后才进 session_state，编辑不触发 rerun；**编号 1-based → 传给事件层前 -1**，曾因整体错位一位导致事件身份与候选不匹配、确认后候选不消失）；手动添加表单用显式 `key="behavior_manual_panel"` 防止 selectbox 改值触发 rerun 后收起（无 key expander 收起是已知 bug 类，与②阶段 history_panel 同源）；已确认事件分方向列出（可编辑 / 删除 / 记主观感受，主观感受明示“不是对方意图的客观证据”）；长期行为事件报告（Markdown 下载 + 事件 JSON 导出）。事件按 friend_id 隔离；同一事件重复导入按事件身份（指纹集合 + 方向 + 行为类型）去重，DB 部分唯一索引兜底。Phase 2A.1：候选 / 手动表单的控件 key 作用域 = friend_id + 聊天案例签名 + 分析版本 + 事件身份（`_behavior_scope`，跨好友/跨聊天不串味——旧实现只用事件身份，切换好友会继承上一位的备注与片段）；历史候选项禁用边界编辑并明示编号属于原 run；三条保存路径都有「最终会写入档案的内容」脱敏预览；手动表单默认编号 1/2（不 fill——number_input 的 fill 会触发异步 rerun 落在 combobox 两连击之间）。Phase 2A.1 终版：候选 / 手动 / 事件编辑三条路径共用 `_behavior_final_preview` 两阶段门控——「查看最终预览」是显式第二步（该 Streamlit 版本 textarea **击键不触发 rerun、失焦才提交**，真实浏览器实测），预览给出**最终将写入档案**的脱敏+截断内容与事件摘要，保存按钮只在预览未过期时出现，保存处理器还二次校验片段未被预览后修改；候选被安全上限截断时 `bv.truncation_notice` 在主界面明确提示「部分候选未显示」+ 实际数量，正常规模不显示

## Hard constraints (change only with explicit user approval)

- Do not alter the v2 aggregation formula in `scoring.py` or the semantics of the Jev questions.
- Changing the Jev question set **requires bumping `SCHEMA_VERSION` in `analyzer.py`** (currently `chat-signal-v3.3`): the cache key hashes it, so old entries invalidate naturally. Never delete `.jev_cache`. The same bump is required when a question's **semantics** change — including description-only edits: v3.3 sorted the merged multi-chunk timeline before Context Builder (a data-correctness fix: newest-first chunk appends used to reverse the list, leaking future messages into context) with no question, scoring or judgment change; v3.2 redefined `engagement` as the message's actual contribution to the interaction (not topic agreement, not intimacy; topic refusal with follow-up questions, temporary busyness with concrete plans, and polite closes with concrete content are no longer mechanically low engagement; repeated substance-free replies or explicit refusal to continue are; and engagement is explicitly decoupled from `distancing_signal`); v3.1 refined `distance`'s description (topic refusal / romantic boundary / relationship withdrawal share that label), layered `warmth`, made `relationship_evidence_strength` explicitly information-not-direction, and added an ambiguity clause to emotion/intent; v3.0 narrowed `distancing_signal` to relationship-level withdrawal; v2.2 changed context selection + the outbound allowlist. scoring formulas/weights are unchanged.
- Never send media placeholders (`[图片]`, `[视频]`, `[动画表情]`, `[语音]`, `[文件]`) to Jev as analyzable text: Jev has no image input and the copied text contains no actual media. Pure-media messages must stay non-targets; in context they become neutral markers whose content must never be guessed. No vision model, no OCR, no `.dat`/`.mp4` reading.
- Never send `raw_speaker`, raw nicknames, chunk metadata, fingerprints, media binaries, or other parser-only fields to Jev. Keep the outbound allowlist enforced in `build_state()` and covered by tests.
- **Before changing the Jev questions, Context Builder, or scoring, run the benchmark first** (`python scripts/evaluate.py --fixtures`, or a saved real-mode report) and report baseline vs candidate via `--compare`. The evaluation harness is the quality gate for algorithm changes; its pass rate is a regression signal on human-defined cases, **not** a scientific accuracy claim, and must never be packaged as one.
- Report export must stay **zero-API**: pure functions over already-computed results/stats, no generative LLM.
- `storage.Cache` must keep **short-lived connections** (`_connect()` per operation). A long-lived `sqlite3.Connection` breaks under Streamlit reruns with a cross-thread `ProgrammingError` — this was a real bug; do not reintroduce it.
